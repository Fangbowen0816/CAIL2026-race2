# 错别字修订模块优化（typo guard）

> 起因：线上 `Rev_typo 61.70`（精度 58.1% / 召回 82.0%，`FP=341`）。目标：**保召回、砍 FP**。
> 参考：pycorrector（EC-LAW 法律域纠错，微调 Qwen 可达 F1 0.94–0.98）+ 混淆集约束思路。

## 一、先验证（改之前必须知道错在哪）

对 45 合同做**字符级 diff 审计**（`scripts/audit_typo_edits.py`）。5 gold 对照：typo 段只做
**1–2 处等长同音替换**（共→供、城→成），与 gold 完全一致 → 机制本身正确。

纯 typo 段（166）的编辑分类（初版）：

| 类别 | 数量 | 判定 |
|---|---:|---|
| 同音替换（措→错） | 179 | ✅ 真纠错 |
| **词序颠倒**（要主→主要、定约→约定、风台→台风） | 36 | ✅ 真纠错（diff 表现为 插入+删除） |
| 少字补全（不足→不足以） | 25 | ✅ 真纠错 |
| 重复字/标点删除、补括号 | 59 | ✅ 真纠错 |
| **集外替换**（甲→乙、达到→弥补） | 33 | ❌ 多为改写 |
| **空白差异**（删空格/Tab/NBSP） | 21 | ❌ 非错字 |
| **当事人/数字变动** | 12 | ❌ 非错字 |
| 非重复删除、长度不等改写 | 15 | ❌ 多为改写 |

→ **结论：确有"改错"（空白/专名/集外/结构 约 81 处），但多数编辑仍是真纠错**；
**词序颠倒与少字是"看起来像垃圾、其实是真纠错"的陷阱**，必须保留。

## 二、优化：`src/cail_race2/typo_guard.py`（确定性后置校验）

| 规则 | 行为 |
|---|---|
| G1 空白保真 | 仅空白差异 → 回退 |
| G2 专名/数字保护 | 当事人称谓（甲/乙/丙/丁）与数字的增删改 → 回退 |
| G3 混淆集闸门 | 汉字替换须"同音或形近"（`resources/confusion/{same_pinyin,same_stroke}.txt` + pypinyin + 补充形近表） |
| G4 词序颠倒 | 相邻 `insert(X)/delete(X)` 配对 → **保留** |
| G5 少字补全 | 插入 1–2 个汉字/常用标点 → **保留** |
| G6 结构/改写 | 长度不等改写、非重复删除 → 回退 |

- 生效范围：**纯 typo 段走全规则**；其他段仅**空白保真**（避免误伤 stance/missing 的合法改写）。
- 迭代到不动点（最多 6 轮）；已接入 `LLMReviseStage`（`guard_records`）。

## 三、检测机制：`scripts/typo_check.py`

无 45 合同 gold，故建**规则代理指标**：
```
合法纠错 legit = 混淆集内替换 + 词序颠倒 + 少字补全 + 重复字/标点删除 + 补括号
违规编辑 viol  = 空白差异 + 当事人/数字变动 + 集外替换 + 非法插入/删除 + 长度不等改写
precision 代理 = legit / (legit + viol)
```

## 四、结果（同一份 semi_kdeep 预测，离线校验，不花线上额度）

| 范围 | 指标 | 校验前 | 校验后 |
|---|---|---:|---:|
| **纯 typo 段(166)** | 编辑总数 | 362 | **281** |
| | 合法纠错 | 281 | **281（零损失）** |
| | 违规编辑 | 81 | **0** |
| | precision 代理 | 0.7762 | **1.0** |
| **typo 混段(105)** | 空白违规 | 66 | **0** |
| | 合法纠错 | 207 | **207（零损失）** |

- **5 gold 回归**：`Total 88.2798 / Rev_typo 100.0` **前后完全一致**（零回归）；
- **单测**：新增 20 例 → **206 passed**；
- **产出**：`outputs/semi_kdeep_g/`（修订 1149 条，被校验改动 115 条），`preflight` **0 ERROR**。

## 五、预期收益

若被清除的 147 处确为 gold 错字段落内的 FP：`FP 341 → ~194` → `F0.5 61.70 → ~72.9`
（**Rev_typo +11.2 → Total 约 +0.56**）。保守估计也有 **+0.25 ~ +0.56**。
额外收益：**不再破坏空白/当事人/编号**，对 missing/stance 的修订稳定性有益。

## 六、下一步
1. 提交 `semi_kdeep_g` 验证（对照 R2 = 27.6117）；
2. 若 `Rev_typo` 上升，则把混淆集扩到"同韵母"级别（`鉴/签` 现被误判为集外）；
3. 可选：引入 `EC-LAW` 作域内校准集 / 微调小模型（Qwen-CTC）作投票。

# 第二轮：本地错别字集 + 词典检测器

## 1. 登记错别字集（模型标注）
`scripts/annotate_typos.py`：对每份合同**逐段逐字**穷举错别字（同音/形近/多字/少字/词序/重复标点），
产出 `resources/typo/typo_set.jsonl`（45 合同，**810 处**；5 gold 上 C001 命中 2 处、C002–C005 为 0，与真值一致）。
> 该集由复赛合同文本派生，**已 gitignore，不入公开仓库**。

## 2. 精炼为检测词典
`scripts/build_typo_lexicon.py` → `resources/typo/lexicon.jsonl`（**269 条**）。分类：
`subst 341 / punct 140 / subst-out 124 / num 101 / dup 52 / missing 32 / len 18 / rewrite 2`。
关键过滤（防止"把对的改错"）：
1. **剔除双向歧义**（如 `使用↔适用` 同时出现）；
2. **错形必须是非法词**（jieba 词表校验）：`工做/没备/签定/咨料` 入典，`对方/响应/不足/同一` 等合法词**剔除**；
3. 纯标点类交给 `typo_guard` 的结构规则。

## 3. 检测器 `src/cail_race2/typo_dict.py`
最长匹配、非重叠、左到右；单字条目（`已→以` 这类高风险）自动排除。
`apply_typo_dict()` 对命中段落**补齐 typo 定位与修订**（已接入 `LLMReviseStage`）。

## 4. 检测机制 `scripts/typo_dict_check.py`
| 维度 | 结果 |
|---|---|
| **精度（留出 5 合同）** | 加"非法词"过滤前 P 0.33 → **过滤后 P 0.92**（R 0.12；错字多为一次性，词典天然低召回） |
| **对错别字集的召回** | 全量 45：LLM **71%** ｜ 词典 64% ｜ **合并 78%（+7pp）** |
| | 留出 5：LLM 66% ｜ 词典 29% ｜ 合并 66%（**词典不跨合同泛化**，价值在"同批内一致") |
| **安全性** | `wrong==right` 条目 0；5 gold 回归 `Rev_typo` 保持 **100** |

## 5. 产出
`scripts/apply_typo_guard.py --dict --contracts <f>` → `outputs/semi_kdeep_gd/`：
**typo 定位 271 → 323（+52）**，修订 1149 → 1181，`preflight` **0 ERROR**。

## 6. 结论与限制
- **收益**：确定性词典把**反复出现的错字在整份合同内改全**（LLM 常只改一处），并补齐漏段；
- **限制**：词典**不跨合同泛化**（新合同的错字拿不到）→ 对封测帮助有限，对**固定测试集**帮助明确；
- **单测**：214 passed。

# 第三轮：通用错别字词典 + 合同集只作验证

## 1. 职责分离（关键纪律）
| 资源 | 用途 | 是否入库 |
|---|---|---|
| `resources/typo/general.jsonl` | **通用词典**（公开资源构建）→ 算法用 | ✅ 入库 |
| `resources/typo/public/*.tsv` | 公开 CSC 语料（SIGHAN/MCSC/EC-LAW） | ✅ 入库 |
| `resources/confusion/*.txt` | 混淆集（pycorrector, Apache-2.0） | ✅ 入库 |
| `resources/typo/contract/` | **合同错别字集（810）** → **仅验证，agent 不查询** | ❌ gitignore |

## 2. 通用词典的构建（`scripts/build_general_lexicon.py`）
- **公开语料抽取**：SIGHAN-2015 425 对 + MCSC 718 对 + EC-LAW 724 对（均为公开、非竞赛数据）；
- **混淆集生成**：常用词 × 同音/形近替换 → 保留"**错形非法词、正形合法词**"的对；
- 过滤：剔双向歧义、错形须不在 jieba 词表；
- 产出：**19,547 条**（780 KB），零竞赛数据。

## 3. 算法：`TypoDict`（最长匹配 + **分词边界门控**）
门控修复了最致命的伪命中（`共和国`→"和国"、`工作日`→"作日"、`甲方在`→"方在"）：
命中须**首尾都落在 jieba 分词边界**且不在更长词内部。

## 4. 验证：`scripts/typo_validate.py`（对合同错别字集，agent 不查）
| 版本 | 精度 | 召回 |
|---|---:|---:|
| 朴素词典（无门控） | 0.045 | 0.117 |
| + 子串边界 | 0.077 | 0.067 |
| + 分词首尾门控 | **0.243** | 0.053 |
| 仅公开语料对（138 条） | — | **0（合同里 0 命中）** |

**对错别字集的召回**：LLM **71%** ｜ 通用词典 20% ｜ 合并 74%。

## 5. 结论（诚实）
1. **通用静态词典在本领域不可用**：残存误命中几乎全是**函数字碎片**（`元整/日为/在本/的或`），
   实测精度 0.12–0.24 → **既不自动改写、也不注入提示**（已回退）；
2. **公开域语料对合同几乎无覆盖**（138 条词对在 45 合同中 0 命中）——合同错字是**领域短语**
   （`不足弥补→不足以弥补`、`壹拾贰万元整→壹拾伍万元整`），通用词典拿不到；
3. **真正有效的用法**是第一轮的 `typo_guard`：把公开**混淆集当作 LLM 修订的精度闸门**（拒绝集外替换/空白/专名改动），
   纯 typo 段违规 81→0、合法纠错 0 损失；
4. 若要接近 pycorrector 在 EC-LAW 上的 F1 0.94–0.98，需**神经纠错模型微调**（Qwen-CTC/MacBERT），
   而非词典——这是后续可选项。
