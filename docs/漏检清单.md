# 当前算法 + LLM 的漏检清单

> 结论来自实测：示例（gold）与 15 合同（三模型多数参考）。用于指导 #20/#26/#27。
> 更新：2026-11-15。

## 一、按错误类型的漏检

### typo（错别字）
- **确定性无任何检测**（100% 靠 LLM）。
- 漏检点：形近字/专有名词内部错字、**跨字符**错字（如「完城」缺「完成」的相对时间语义）。
- 现状：LLM 表现尚可（线上 `Loc_typo 90.91`），但**无兜底**，LLM 漏即全漏。

### inconsistency（不一致）
- 确定性**只抓同槽位冲突**：当事人名、`money/总价`、`code`。
- **无检测**的冲突类型：
  - **数值型**：分期合计≠总价、单价×数量（部分覆盖）、比例×基数（部分覆盖）；
  - **日期/期限不一致**（起止日期与期限不符）；
  - **地点/地址不一致**（同主体两处地点不同）；
  - **义务/条件不一致**（同一义务在不同条款表述冲突）；
  - **主体关联不一致**（简称/全称、甲方/乙方混用）。
- 结果：这些**全压给 LLM**，LLM 漏则漏。

### missing_element（要素缺失）
- 确定性只抓**有表面痕迹**的：强/弱标记、占位符、空字段、义务段无时间。
- **完全无检测**的情形：
  - **无任何痕迹**的缺失——例：示例 `C001 p4「乙方负责将货物送至甲方指定仓库。」`（无交付时间，但无标记）；
  - **合同类型特有必要要素**：租期、押金、验收标准、知识产权归属、保密期限、违约计算方式；
  - **引用型缺失**：写「详见附件 X」但附件未给。
- 证据：**三模型一致报出的 39 个缺失里，模块完全没检出 22 个**（全靠 LLM）。

## 二、由「事实抽取」缺陷导致的漏检（第 2 步）
- 中文数字金额（`壹佰陆拾万元`，21 处，95% 冗余但仍有漏）；
- **标签变体/空格标签**（`甲 方`、`供方/需方/出租方/承租方/受托方/开户名称/户名…`，30+ 处）→ 漏当事人；
- **无标签机构名**（43 处）；
- **地点/地址类完全未建模**（79 段）。
- 影响：`find_conflicts` 分组缺项 → 漏名称/编号冲突。

## 三、由「补写」缺陷导致的漏检（第 6 步）
- 确定性补写只覆盖 `payment_time / delivery_time / acceptance_time / service_time`（约 24%）；
- 金额、数量、违约责任、保密期、验收标准等要素**无模板**，全靠 LLM 自由补写；
- 相对时间守卫（#13）可能**过紧**：线上 `Loc_missing` 从 29.01 降到 26.72。

## 四、由「模型/工程」导致的漏检
- **单模型非确定性**：同合同两次跑定位原子 Jaccard 约 **0.578** → 单次必然漏一部分；
- 长合同（100+ 段）**中间段**易漏（未定量验证）；
- 并行/缓存中断会丢合同（曾出现 `PermissionError` 导致单合同缺失）。
