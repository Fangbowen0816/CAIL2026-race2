# 设计形态（2026-11-15 本轮设计后 · 第 2 版）

> 对齐「管线各阶段 ↔ issue」。两处关键决策：
> ① 原「第 7 步无条件覆盖」**降级为兜底**；② S7 用**纯规则复核**，其后再加一轮**跨模型审稿**。

## 一、目标管线

```
输入 contracts.jsonl
  │
S0 解析          parse_paragraphs                    —— 已实测无损
  │
S1 归一化  [#29] 产出 normalized_paragraphs（无错字底稿）
  │              ※ 输出 original_text 仍回填「输入原文逐字」
  │
S2 事实抽取      facts.py  [#22 #23 #24 #25]         —— 在干净文本上抽
  │
S3 空缺检测 [#26] 降噪 + 提召回；强候选**默认仅 hints**
  │
S4 定位(LLM 主导) [#27 #20] 压过度报告 + 补遗漏
  │
S5 归类 [#28]    复用 revise-LLM 输出 missing_kinds（支持多类）
  │
S6 句级改写       [#30 #31 #32] evidence + 整句交模型；代码只做整段替换
  │              ※ 旧「确定性补写」降级为**兜底**（非覆盖）
  │
S7 纯规则复核 [#33] R1–R8 可核查规则，**零模型调用**；拒绝回退原文
  │
S7.5 跨模型审稿 [#34] 用**独立模型（≠S6 生成器）**裁定语义；拒绝回退原文
  │
S8 合法性检查      只查格式硬约束（error_types 自洽 / original 逐字 / 无标签 …）
  │
输出 localization_predictions.jsonl + revision_predictions.jsonl
```

## 三、本轮变更记录

1. **第 7 步（确定性覆盖）→ 降级为兜底**（示例零贡献、15 合同负贡献）。归入 **#32**。
2. **第 8 步 → 只做合法性检查**（不做内容判断）。
3. **S7 = 纯规则复核**（#33）：R1 只改目标句 / R2 幅度 / R3 插入锚点安全（词边界）/ R4 未删原文 /
   R5 不引入新冲突 / R6 与 evidence 一致 / R7 格式 / R8 确定性。**零模型调用**，**否决式**。
4. **S7.5 = 跨模型审稿**（#34）：S7 判不了「改得小但语义错」，用**独立模型**补；
   必须**不同于 S6 的生成模型**（否则自审失效）。
5. **归类走「复用 LLM kind」**（#28）；**生成不做多候选**（#31）。

## 四、三层把关的边界
```
S6   生成：约束 + evidence + 结构守卫      → 「改对」
S7   复核：R1–R8 规则，零模型，否决式      → 「没改坏」（可复现）
S7.5 审稿：独立模型裁定语义               → 「语义没错」（补 S7 的盲区）
S8   合规：平台格式硬约束                 → 「不会被退回」
```
