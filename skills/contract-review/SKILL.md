# 合同审查 Skill

## 何时使用
拿到一份（或一批）中文合同，需要找出问题、给出修订建议，并交付「批注合同 + 审查报告」时使用。

## 方法（四步）

1. **解析**：合同按 `<p id="N">正文</p>` 分段，编号即定位单位。
2. **确定性预分析**（不调用模型）：正则抽取当事人、金额、数量、比例、日期、期限、编号；
   交叉比对得到疑似冲突（当事人名不一致、单价×数量≠总价等）与缺失标记（另行协商/待定/空字段）。
3. **语义审查**（模型）：在预分析线索辅助下通读全文，定位三类问题：
   - `typo` 错别字——可根据上下文还原的错字、漏字、多字。
   - `inconsistency` 上下文不一致——同一事项的名称/金额/日期/数量/义务相互冲突。
   - `missing_element` 要素缺失——已有条款缺少必要信息（如交付时间仍写“另行协商”）。
4. **修订**：对每个问题段给出完整最终正文；不一致须同步全部冲突段；要素缺失须补出**具体**信息。

## 产出（写入工作区，路径必须向用户报告）
- `annotated.md` —— 逐段批注合同。
- `report.md` —— 问题清单与修订说明。
- `localization_predictions.jsonl` / `revision_predictions.jsonl` —— 可评测的结构化结果。

## 执行方式
优先用工作区现有能力执行本方法（`run_shell` 运行仓库脚本）：
```
python -m agent.review --contract <合同文件路径> --out <输出目录>
```
脚本会复用确定性预分析 + 模型审查；如干跑（`--dry`）则只做确定性预分析。
