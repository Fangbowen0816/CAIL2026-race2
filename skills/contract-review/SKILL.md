# 合同审查 Skill

## 何时使用
拿到一份（或一批）中文合同，需要：找出问题 → 给出修订 → 交付「批注合同 + 审查报告 + 可评测结果」。

## 能力边界
- 只做**文本层面**的问题发现与修订建议，不提供法律意见、不替代律师。
- 问题限定三类：`typo`（错别字）、`inconsistency`（上下文不一致）、`missing_element`（要素缺失）。
- 定位单位为**段落编号**（合同以 `<p id="N">正文</p>` 标注）。

## 方法（四阶段）

### 阶段 1 · 解析
输入合同原文，按 `<p id="N">` 切段，得到 `{段落号: 正文}`。段落正文做 HTML 反转义（与平台口径一致）。

### 阶段 2 · 确定性预分析（不调用模型）
用规则从全文抽取事实并交叉比对，作为后续语义审查的**线索**：
- **事实抽取**：当事人（甲方/乙方…）、金额（元/万元/亿元）、数量、比例、日期、期限、编号，各自带段落号与槽位。
- **一致性冲突**：同一槽位出现不同取值（当事人名、合同总价、合同编号）；单价×数量≠总价；比例×总价≠金额。
- **缺失标记**：含「另行协商/另行约定/待定/空字段」等；交付/付款类条款段内未见时间。
> 预分析是**线索**不是结论，须由模型结合全文复核。

### 阶段 3 · 语义审查（模型，读全文 + 线索）
在预分析线索辅助下通读全文，定位三类问题（判定细则见 `references/审查要点.md`）：
- 跨段不一致必须列出**全部**冲突位置，不能只报准备修改的一侧。
- 要素缺失要**主动查**：交付/付款时间、金额、数量、违约责任等，即使没有「另行协商」字样，若相应条款未给出具体值，也应判为缺失。

### 阶段 4 · 修订
对每个问题段给出**完整最终正文**：
- 不一致：选定一套取值并**同步全部相关段**；算术冲突按关系重算（单价×数量=总价、比例×总价=金额）。
- 要素缺失：补出**具体**信息（可依据全文推导；无法确定时给出合理且内部协调的约定），不得只写「另行协商」。
- `original_text` 由系统按定位回填，必须与原文逐字一致。

## 产出物（写入工作区，须向用户报告路径）
| 文件 | 内容 |
| --- | --- |
| `annotated.md` | 批注合同：逐段标注问题类型与修订 |
| `report.md` | 审查报告：问题清单、预分析线索、修订说明 |
| `localization_predictions.jsonl` | 定位记录（格式见 `references/输出格式.md`） |
| `revision_predictions.jsonl` | 修订记录（格式见 `references/输出格式.md`） |

## 自检清单（提交前）
- [ ] `sample_id`/`contract_id` 覆盖全部输入，无缺无多无重复；
- [ ] `location` 升序、互不重叠，段落编号真实存在；
- [ ] `error_type ∈ {typo,inconsistency,missing_element}`；
- [ ] 修订段 `error_types` == 该段定位类型并集（否则平台整体退回）；
- [ ] `original_text` 与输入段落逐字一致；`correct_answer` 非空、不含段落标签；
- [ ] 无错误合同：定位写 `{location: [], error_type: null}`，修订写空哨兵。

## 常见坑
| 现象 | 处理 |
| --- | --- |
| 平台报 `original_text must exactly match` | 段落正文需 HTML 反转义（`&lt;table&gt;`→`<table>`） |
| 平台整体退回 | 检查上述自检清单第 3 条（error_types 自洽） |
| 跨段不一致只改一侧 | 修订须同步所有冲突段 |
| 把「详见附件」一律判缺失 | 信息在其他条款已明确的不算缺失 |

## 执行方式
优先复用工作区现有能力（`run_shell` 运行仓库脚本）：
```
python -m agent.review --contract <合同文件> --out <输出目录> [--dry]
```
`--dry` 仅做确定性预分析（不调用模型），用于快速查看线索。
