# 输出格式规格（两份 JSONL）

## 1. `localization_predictions.jsonl`
每行一个问题组，字段 **3 个**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `contract_id` | string | 合同编号（须与输入一致） |
| `location` | array \| null | 升序、不重叠的段落闭区间列表；无问题为 `[]` |
| `error_type` | string \| null | `typo` / `inconsistency` / `missing_element`；无问题为 `null` |

```json
{"contract_id":"C001","location":[[2,2]],"error_type":"typo"}
{"contract_id":"C001","location":[[1,1],[3,3]],"error_type":"inconsistency"}
{"contract_id":"C001","location":[[4,4]],"error_type":"missing_element"}
{"contract_id":"C002","location":[],"error_type":null}
```

## 2. `revision_predictions.jsonl`
每行一个**被修改段落**的最终文本，字段 **5 个**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `contract_id` | string | 合同编号 |
| `location` | array \| null | 正常记录只能是单点区间 `[[p,p]]`；无修改为 `[]` |
| `error_types` | array | 该段定位类型并集（去重、排序）；无修改为 `[]` |
| `original_text` | string \| null | 该段**原文逐字**（不含 `<p>` 标签）；无修改为 `null` |
| `correct_answer` | string \| null | 该段**完整最终正文**（不含 `<p>` 标签）；无修改为 `null` |

```json
{"contract_id":"C001","location":[[2,2]],"error_types":["typo"],"original_text":"乙方应向甲方提共办公桌20张。","correct_answer":"乙方应向甲方提供办公桌20张。"}
{"contract_id":"C001","location":[[3,3]],"error_types":["inconsistency","typo"],"original_text":"乙方北辰办公设备有限公司应在验收完城后开具发票。","correct_answer":"乙方远山办公设备有限公司应在验收完成后开具发票。"}
{"contract_id":"C002","location":[],"error_types":[],"original_text":null,"correct_answer":null}
```

## 3. 硬性校验（不满足会被平台整体退回）
1. `location` 区间升序、不重叠，编号真实存在；`start ≤ end`。
2. `error_types` **必须等于**该段定位记录的类型并集（`revision.reconcile` 强制保证）。
3. `original_text` 与输入段落**逐字一致**（段落正文需 HTML 反转义）。
4. `correct_answer` 非空、不含段落标签（`<p …>`）。
5. 同一 `contract_id` 下同一 PID **不得重复修订**。
6. `contract_id` 必须覆盖输入文件全部样本。

## 4. 段内边界情况
- **无问题合同**：定位写 `{"location":[],"error_type":null}`；修订写空哨兵 `{"location":[],"error_types":[],"original_text":null,"correct_answer":null}`。
- **同段多类问题**：定位分别报告；修订一次给出该段完整最终文本，`error_types` 为类型并集。
- **表格/转义段落**：原文含 `&lt;table&gt;` 等实体时，`original_text`/`correct_answer` 用反转义后的文本。
